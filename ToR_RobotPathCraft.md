# Техническое задание

## Приложение RobotPathCraft

### Система автоматизированного проектирования траекторий для мехатронных систем

---

## 1. Общее описание

**RobotPathCraft** — десктопное приложение на Python с графическим интерфейсом для автоматизированного проектирования траекторий движения мехатронных систем. Приложение позволяет загружать карту рабочего пространства, задавать параметры движения, рассчитывать оптимальный путь с помощью алгоритмов поиска и визуализировать результаты.

**Целевая аудитория:** инженеры-мехатроники, разработчики робототехнических систем, студенты технических специальностей.

## 3. Функциональные требования

### 3.1 Загрузка карты

Приложение должно поддерживать загрузку карты рабочего пространства в следующих форматах:

- **PNG / JPG** — изображение карты, где тёмные пиксели интерпретируются как препятствия, светлые — как свободное пространство. Пользователь может настраивать порог бинаризации.
- **JSON** — структурированный файл, описывающий сетку препятствий, размеры поля, координаты точек.
  ```json
  {
    "width": 100,
    "height": 100,
    "obstacles": [[10,20], [11,20], ...],
    "start": [5, 5],
    "goal": [90, 90]
  }
  ```
- **CSV** — матрица значений, где `0` — свободная клетка, `1` — препятствие.

После загрузки карта отображается в области визуализации.

### 3.2 Параметры движения (задаются в интерфейсе)

Все параметры вводятся непосредственно в панели управления GUI:

| Параметр                   | Описание                                      | Тип ввода         |
| -------------------------- | --------------------------------------------- | ----------------- |
| Начальная точка (X, Y)     | Координаты старта                             | Числовые поля     |
| Конечная точка (X, Y)      | Координаты цели                               | Числовые поля     |
| Алгоритм поиска            | A\* или RRT                                   | Выпадающий список |
| Максимальная скорость      | м/с, используется для расчёта времени         | Числовое поле     |
| Радиус поворота            | Минимальный радиус для кинематического агента | Числовое поле     |
| Шаг сетки / шаг расширения | Разрешение для A\* / длина ветки для RRT      | Числовое поле     |
| Допустимое отклонение      | Радиус достижения цели                        | Числовое поле     |
| Сглаживание траектории     | Включить / отключить постобработку            | Флажок (checkbox) |

Точку старта и финиша также можно задать кликом по карте в области визуализации.

### 3.3 Расчёт траектории

- Пользователь нажимает кнопку **«Рассчитать»**.
- Приложение запускает выбранный алгоритм поиска пути:
  - **A\*** — поиск по сетке с эвристикой (Манхэттен или Евклид).
  - **RRT** (Rapidly-exploring Random Tree) — вероятностный метод, пригодный для непрерывного пространства.
- Если путь найден — результат передаётся на визуализацию и в блок рекомендаций.
- Если путь не найден — пользователь получает сообщение с причиной (недостижимая цель, старт/финиш внутри препятствия и т.д.).
- Во время расчёта отображается индикатор прогресса.

### 3.4 Визуализация результатов

Результаты отображаются в основной области приложения (Matplotlib Canvas):

- Карта рабочего пространства с отмеченными препятствиями
- Начальная точка (зелёная метка) и конечная точка (красная метка)
- Найденная траектория (синяя линия)
- Для RRT — опционально дерево поиска (серые линии)
- Длина пути и ориентировочное время в движении отображаются под графиком
- Доступны кнопки масштабирования и сохранения изображения

### 3.5 Текстовые рекомендации

После расчёта в отдельном текстовом блоке интерфейса формируется отчёт:

```
✅ Траектория найдена
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
📏 Длина пути:         145.3 ед.
⏱  Расчётное время:   7.2 с (при v_max = 20 ед/с)
↩  Количество поворотов: 8
⚠  Узкие участки (ширина < 2 ед.): 2 обнаружено
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Рекомендации:
• Участок [23,45] → [31,45]: снизьте скорость до 30% из-за
  ограниченного пространства манёвра.
• Рассмотрите альтернативный маршрут через [60,30] для
  уменьшения числа поворотов.
• Траектория проходит в 2 ед. от препятствия на отрезке
  [70,60]→[80,65] — рекомендуется увеличить запас.
```

## 5. Алгоритмическая часть

### 5.1 Алгоритм A\*

- Работает на дискретной сетке, построенной из загруженной карты
- Эвристика — Евклидово расстояние (или Манхэттен для 4-связной сетки)
- Поддержка 8-связной сетки (включая диагональные переходы)
- После нахождения пути — опциональное сглаживание (удаление лишних узлов методом «разрыва видимости»)

### 5.2 Алгоритм RRT

- Работает в непрерывном двумерном пространстве
- Параметр: длина шага расширения (step_size)
- Останавливается при достижении области цели (goal_radius)
- Опционально: RRT\* с ограниченным числом итераций пересоединения для улучшения качества пути

### 5.3 Постобработка траектории

- Сглаживание: алгоритм «shortcutting» (пропуск промежуточных точек при наличии прямой видимости)
- Расчёт метрик: общая длина, количество поворотов, минимальный зазор до препятствий

## 8. Нефункциональные требования

- **Производительность:** расчёт A\* на сетке 500×500 — не более 5 секунд; RRT с 5000 итерациями — не более 3 секунд.
- **Платформа:** Windows 10+, Linux (Ubuntu 20.04+). MacOS — желательно.
- **Документация:** каждый модуль содержит docstring; в корне проекта — `README.md` с инструкцией по установке и запуску.
- **Обработка ошибок:** все исключения перехватываются и отображаются в виде диалоговых окон, приложение не падает с необработанным traceback.
